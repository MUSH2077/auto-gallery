# 远程访问约束

## 规则

v1 中系统针对 NAS 局域网部署设计。远程客户端访问必须通过网络层方案提供，而非将应用直接暴露到公网。应用代码不得实现自己的面向公网的安全机制。

## 访问层级

### v1（当前）：仅局域网

- 所有服务在内部 Docker 网络上
- 后端 API 端口（`BACKEND_PORT`，如 8818）暴露在 NAS 局域网
- 管理后台端口（`ADMIN_WEB_PORT`，如 3000）暴露在 NAS 局域网
- 客户端（Flutter）在同一网络时通过局域网 IP 连接
- 不暴露到公网
- 不需要 HTTPS（局域网 HTTP 在 v1 可接受）

### v1.5（可选）：VPN 访问

用于不暴露公网的远程客户端访问：

- **推荐**：Tailscale（个人使用免费，设置简单）
- **备选**：NAS 或路由器上的 WireGuard VPN 服务器
- 客户端通过 VPN IP 连接 NAS（Tailscale 为 `100.x.x.x`）
- 无需应用更改——API 和媒体端点工作方式相同
- 仍不需要 HTTPS（VPN 提供加密层）

### v2（未来）：带 HTTPS 的反向代理

用于受控的公网暴露（如果 VPN 不可接受）：

- **推荐**：NAS 上的 Caddy 或 Nginx 反向代理
- **备选**：Cloudflare Tunnel（路由器无需开放端口）
- 通过 Let's Encrypt（Caddy 自动）或 Cloudflare 源证书实现 HTTPS
- 反向代理处理 TLS 终止；后端服务内部保持 HTTP
- 防火墙：仅允许 443（HTTPS）从公网入站

## 应用代码不得实现

- TLS/HTTPS 处理（留给反向代理）
- IP 允许/阻止列表（留给防火墙或 VPN）
- DDoS 防护（留给反向代理 / Cloudflare）
- 端口转发逻辑
- 动态 DNS

## 应用代码必须实现

- 容器内绑定到 `0.0.0.0`（Docker 网络要求）
- CORS：仅允许已知来源（管理后台局域网 IP，不用通配符）
- 在反向代理后时信任 `X-Forwarded-For` 和 `X-Forwarded-Proto` 头（通过环境变量 `BEHIND_PROXY=true` 配置）
- 认证端点限流（`/api/v1/auth/*`）：每 IP 每分钟最多 10 次请求
- 媒体端点限流（`/media/*`）：每用户每分钟最多 100 次请求（防止单个客户端占满 NAS I/O）

## 网络架构

```
┌─────────────────────────────────────────────────┐
│  公网（仅 v2，通过反向代理）                      │
│  HTTPS :443 → Caddy/Nginx                       │
└──────────────────┬──────────────────────────────┘
                   │ 此处 TLS 终止
┌──────────────────▼──────────────────────────────┐
│  NAS 局域网                                       │
│  ┌─────────┐  ┌──────────┐  ┌───────────────┐   │
│  │ backend │  │admin-web │  │ postgres/redis │   │
│  │ :8818   │  │ :3000    │  │ /meilisearch  │   │
│  └────┬────┘  └────┬─────┘  │ (内部)        │   │
│       │            │        └───────────────┘   │
│       └─── LAN ────┘                             │
│            │                                     │
│  ┌─────────▼────────┐                            │
│  │ 客户端 (Flutter)  │                            │
│  │ LAN 或 VPN       │                            │
│  └──────────────────┘                            │
└─────────────────────────────────────────────────┘
```

## 远程访问的认证

客户端远程连接时：
- JWT token 通过 HTTPS（v2）或 VPN 加密连接（v1.5）传输
- 绝不在局域网外的纯 HTTP 上传输凭据
- 客户端 token 存储：平台安全存储（Flutter：`flutter_secure_storage`）
- Refresh token 轮换：每次刷新使前一个 refresh token 失效

## v1 明确不支持的功能

- 直接公网暴露
- HTTPS（除非在用户管理的反向代理后）
- 多因素认证
- OAuth / 社交登录
- IP 地理位置拦截
- 入侵检测
